Why Playwright Locators?

Auto-waiting

No explicit waits needed

Auto-retry

Resilient to timing issues

User-centric

How users see elements

Old Way (Selenium/XPath)

// Brittle, developer-view await page.click('#submit-btn-123'); await page.waitForSelector('button'); await page.click('//div[@class="row"]/button[2]');

Playwright Way

// Resilient, user-view await page.getByRole('button', { name: 'Submit' }).click(); // Auto-waits, clear intent!
Think like a user, not a developer!

Locator vs ElementHandle

Locator (Recommended)

// Lazy evaluation const button = page.getByRole('button'); await button.click(); // Queries NOW
  • Auto-waits for element
  • Auto-retries on failure
  • No stale element issues
  • Better error messages
  • Lazy evaluation

ElementHandle (Legacy)

// Immediate query const button = await page.$('button'); await button.click(); // May be stale!
  • No auto-waiting
  • No auto-retry
  • Stale element errors
  • Generic error messages
  • Immediate evaluation
Always use Locators! ElementHandles are legacy.

Understanding Web Accessibility

Accessibility = How assistive technologies & users perceive elements

What is Accessibility?

  • Making web usable for everyone
  • Includes people with disabilities
  • Screen readers, keyboard navigation
  • Semantic HTML is crucial
  • ARIA (Accessible Rich Internet Applications)

Who Benefits?

  • Visual impairments: Screen readers
  • Motor disabilities: Keyboard-only
  • Cognitive disabilities: Clear labels
  • Everyone: Better UX overall

Good Accessibility

<!-- Semantic button --> <button>Submit</button> <!-- Input with label --> <label for="email">Email</label> <input id="email"> <!-- Image with alt text --> <img src="logo.png" alt="Company">

Poor Accessibility

<!-- Div as button --> <div onclick="...">Submit</div> <!-- Input without label --> <input placeholder="Email"> <!-- Image without alt --> <img src="logo.png">
Good accessibility = Better testing + Better UX!

ARIA Roles - Accessibility Foundation

ARIA roles define what an element IS and what it DOES

What are ARIA Roles?

  • Define element's purpose/function
  • Implicit roles (semantic HTML)
  • Explicit roles (role attribute)
  • Tell screen readers what element is
  • Foundation for getByRole()

Implicit vs Explicit

<!-- Implicit role="button" --> <button>Click Me</button> <!-- Explicit role --> <div role="button">Click Me</div> <!-- Implicit role="link" --> <a href="/home">Home</a> <!-- Implicit role="textbox" --> <input type="text"> <!-- Implicit role="checkbox" --> <input type="checkbox">
Prefer semantic HTML (implicit roles) over explicit role attributes!

7 built-in strategies + CSS/XPath fallback

1 getByRole() - Most Resilient

Common ARIA Roles

• button

• link

• textbox

• checkbox

• radio

• combobox

• heading

• img

• table

• row

• cell

• dialog

• alert

• navigation

• main

• form

Usage Examples

// Simple role await page.getByRole('button').click(); // Role with name await page.getByRole('button', { name: 'Submit' }).click(); // Regex name match await page.getByRole('link', { name: /sign.?up/i }).click(); // With state filter await page.getByRole('checkbox', { checked: true }).count(); // Heading levels await page.getByRole('heading', { level: 1 }).textContent();
getByRole() = Accessibility + Resilience!

2 getByLabel() - Best for Forms

HTML Label Association

<!-- Method 1: for attribute --> <label for="email"> Email </label> <input id="email" type="text" > <!-- Method 2: Wrapping label --> <label> Username <input type="text"> </label> <!-- Method 3: aria-labelledby --> <span id="user-label"> Username </span> <input aria-labelledby="user-label" >

Usage in Tests

// Exact label match await page .getByLabel('Username') .fill('admin'); // Regex match await page .getByLabel(/email/i) .fill('user@example.com'); // Checkboxes await page .getByLabel('I agree') .check(); // Complete form await page .getByLabel('First Name') .fill('John'); await page .getByLabel('Email') .fill('john@example.com');
getByLabel() = Best for form accessibility!

3 getByText() - Visible Text

HTML Examples

<!-- Text in elements --> <h1>Welcome Back</h1> <p> Your order has been placed </p> <span class="message"> Success! </span> <div> Login successful </div>

Usage in Tests

// Exact text match await page .getByText('Welcome Back') .isVisible(); // Partial text match (substring) await page .getByText('Welcome', { exact: false }) .click(); // Regex match await page .getByText(/welcome back/i) .click(); // Case-insensitive with regex await page .getByText(/success/i) .isVisible(); // Verifying messages await page .getByText('Login successful') .waitFor();
Best for verifying messages, headings, and visible content!

4 getByPlaceholder() - Input Hints

HTML Examples

<!-- Text input with placeholder --> <input type="text" placeholder="Enter your email" > <!-- Search input --> <input type="search" placeholder="Search products..." > <!-- Textarea with placeholder --> <textarea placeholder="Enter your message" ></textarea> <!-- Password input --> <input type="password" placeholder="Password" >

Usage in Tests

// Exact placeholder match await page .getByPlaceholder('Enter your email') .fill('user@example.com'); // Partial match await page .getByPlaceholder('Search', { exact: false }) .fill('laptop'); // Regex match await page .getByPlaceholder(/search.*/i) .type('query'); // Type slowly for autocomplete await page .getByPlaceholder('Search products...') .pressSequentially('phone');
Use when inputs lack labels - but labels are better for accessibility!

5 getByTestId() - When You Control HTML

HTML Examples

<!-- Button with test ID --> <button data-testid="submit-button" > Submit </button> <!-- Container with test ID --> <div data-testid="user-profile" > ... </div> <!-- Custom test attribute --> <input data-test="email-input" > <!-- Form section --> <form data-testid="login-form" > ... </form>

Usage in Tests

// Using data-testid await page .getByTestId('submit-button') .click(); // Access nested elements await page .getByTestId('user-profile') .getByRole('button', { name: 'Edit' }) .click(); // Custom attribute (configure) // playwright.config.ts: // testIdAttribute: 'data-test' await page .getByTestId('email-input') .fill('test@example.com');

When to Use

  • Dynamic content without semantic meaning
  • When you control the codebase
  • Last resort after semantic locators

6 getByAltText() - Image Alt Text

HTML Examples

<!-- Image with alt text --> <img src="profile.jpg" alt="Profile picture" > <!-- Logo image --> <img src="logo.png" alt="Company Logo" > <!-- Product image --> <img src="product.jpg" alt="iPhone 15 Pro" > <!-- Clickable image --> <a href="/profile"> <img alt="User Avatar" > </a>

Usage in Tests

// Click image await page .getByAltText('Profile picture') .click(); // Verify image visible await page .getByAltText('Company Logo') .isVisible(); // Regex match await page .getByAltText(/profile/i) .click(); // Check image loaded const img = page .getByAltText('Product image'); await expect(img) .toBeVisible();
Alt text is essential for accessibility - always use it!

7 getByTitle() - Title Tooltips

HTML Examples

<!-- Button with title --> <button title="Close dialog" > X </button> <!-- Icon button --> <button title="Save changes" > <i class="icon-save"></i> </button> <!-- Link with title --> <a href="/help" title="Get help" > ? </a> <!-- Span with title --> <span title="Information" > ℹ </span>

Usage in Tests

// Click by title await page .getByTitle('Close dialog') .click(); // Partial match await page .getByTitle('Save', { exact: false }) .click(); // Regex match await page .getByTitle(/close|dismiss/i) .click(); // Hover to see tooltip await page .getByTitle('Information') .hover();

Best For

  • Icon buttons without text
  • Close (X) buttons
  • Tooltip elements

Chaining Locators

Narrow down search scope by chaining multiple locators

Basic Chaining

// Chain to search within context await page .locator('.product-card') .getByRole('button', { name: 'Add to Cart' }) .click(); // Navigation menu chaining await page .getByRole('navigation') .getByRole('link', { name: 'Products' }) .click(); // Dialog chaining await page .getByRole('dialog', { name: 'Confirm' }) .getByRole('button', { name: 'OK' }) .click();

Complex Chaining

// Multi-level chaining await page .getByRole('main') .locator('section.products') .getByRole('article') .getByRole('button') .click(); // Table cell in specific row const cellText = await page .getByRole('table') .getByRole('row', { name: /John Smith/i }) .getByRole('cell') .nth(2) .textContent(); // Form in modal await page .getByRole('dialog') .getByLabel('Email') .fill('user@example.com');
Chaining = Precision + Context + Readability

Filtering Locators

Use filter() to narrow down based on specific conditions

Filter by Text

// Exact text filter await page .getByRole('listitem') .filter({ hasText: 'Active' }) .click(); // Regex text filter await page .getByRole('listitem') .filter({ hasText: /active/i }) .click(); // Multiple text filters await page .getByRole('listitem') .filter({ hasText: 'Active' }) .filter({ hasText: 'Priority' }) .click();

Filter by Elements

// Has child element await page .getByRole('listitem') .filter({ has: page.getByRole('button', { name: 'Delete' }) }) .click(); // hasNot - exclude elements await page .locator('.product-card') .filter({ hasNot: page.locator('.out-of-stock') }) .first() .click(); // Complex filtering await page .locator('.product-card') .filter({ hasText: 'iPhone' }) .filter({ has: page.locator('.in-stock') }) .getByRole('button') .click();

Position-based Selection

Methods

// First match await page.getByRole('button').first().click(); // Last match await page.getByRole('button').last().click(); // Specific index (0-based) await page.getByRole('button').nth(2).click(); // Count elements const count = await page.getByRole('button').count(); // Get all elements const buttons = await page.getByRole('button').all(); for (const button of buttons) { await button.click(); }

Use with Caution!

  • Position-based = Brittle
  • Prefer semantic locators
  • Use when truly necessary
  • Document why position used
// ❌ Bad: Fragile await page.locator('button').nth(5).click(); // ✅ Good: Semantic await page .getByRole('button', { name: 'Submit' }) .click(); // ✅ OK: When needed await page .getByRole('listitem') .filter({ hasText: 'Active' }) .first() .click();

Auto-waiting Magic

Playwright automatically waits for elements to be ready

Attached
Visible
Stable
Not Obscured
Enabled

What Playwright Waits For

  • Attached to DOM: Element exists
  • Visible: Not hidden/invisible
  • Stable: Not animating/moving
  • Receives Events: Not covered
  • Enabled: Not disabled

Actions with Auto-wait

  • click(), dblclick(), tap()
  • fill(), type(), press()
  • check(), uncheck()
  • selectOption()
  • hover(), focus()
  • dragTo()
No explicit waits needed! Playwright handles it all.

Locator Strategy Priority

1 getByRole()
2 getByLabel()
3 getByPlaceholder()
4 getByText()
5 getByTestId()

Why This Order?

  • getByRole(): Most resilient, accessibility-first
  • getByLabel(): Best for form inputs
  • getByPlaceholder(): Good for inputs without labels
  • getByText(): Good for visible text content
  • getByTestId(): When you control markup
  • CSS/XPath: Last resort only!

✅ Best Practice

// Resilient to changes await page .getByRole('button', { name: 'Submit' }) .click();

❌ Fragile

// Breaks easily await page .locator('button.btn-primary.submit') .click();

Best Practices

Do This

  • Use user-centric locators (role, label)
  • Make locators descriptive and readable
  • Leverage auto-waiting (no explicit waits)
  • Chain locators for context
  • Use filters to narrow results
  • Prefer semantic over CSS/XPath
  • Create Page Object Models
  • Test for accessibility

Avoid

  • Brittle CSS selectors (classes, IDs)
  • Complex XPath expressions
  • Position-based selection (nth)
  • ElementHandles (use Locators)
  • Explicit sleep/waits
  • DOM structure dependence
  • Hard-coded delays
  • Testing implementation details
Write tests from user's perspective, not developer's!

Real-world Example: Login Form

Test Code

import { test, expect } from '@playwright/test'; test('user login', async ({ page }) => { // Navigate to login page await page.goto('https://example.com/login'); // Fill username (using label) await page .getByLabel('Username') .fill('admin'); // Fill password (using label) await page .getByLabel('Password') .fill('password123'); // Check remember me (using role) await page .getByRole('checkbox', { name: 'Remember me' }) .check(); // Click login button (using role) await page .getByRole('button', { name: 'Login' }) .click(); // Verify successful login await expect(page.getByRole('heading', { name: 'Dashboard' })).toBeVisible(); });

What Makes This Good?

  • Uses getByLabel() for inputs
  • Uses getByRole() for buttons
  • Clear, readable intent
  • No explicit waits needed
  • Resilient to UI changes
  • Accessibility-friendly

Why It's Resilient

  • Works if CSS classes change
  • Works if IDs change
  • Works if DOM structure changes
  • Works if styling changes
  • Auto-waits for all elements

Common Pitfalls to Avoid

Pitfall #1: Brittle Selectors

// ❌ Bad: Depends on CSS classes await page.locator('.btn-primary-lg-submit').click(); // ✅ Good: Semantic and resilient await page.getByRole('button', { name: 'Submit' }).click();

Pitfall #2: Complex XPath

// ❌ Bad: Complex and brittle await page.locator('//div[@class="container"]/div[2]/button').click(); // ✅ Good: Clear intent await page.getByRole('button', { name: 'Save' }).click();

Pitfall #3: Explicit Waits

// ❌ Bad: Manual waiting await page.waitForTimeout(3000); await page.locator('button').click(); // ✅ Good: Auto-waiting await page.getByRole('button').click();

Pitfall #4: Position-based

// ❌ Bad: Position-dependent await page.locator('button').nth(5).click(); // ✅ Good: Semantic selection await page.getByRole('button', { name: 'Delete' }).click();

Understanding Strict Mode

By default, Playwright requires exactly ONE matching element

Why Strict Mode?

  • Prevents accidental clicks on wrong elements
  • Makes tests explicit and clear
  • Catches bugs early
  • Forces precise locators
// If multiple buttons exist, throws error await page.getByRole('button').click(); // Error: strict mode violation // locator resolved to 3 elements

Solutions

// 1. Make locator more specific await page .getByRole('button', { name: 'Submit' }) .click(); // 2. Use first() for first match await page .getByRole('button') .first() .click(); // 3. Use nth() for specific position await page .getByRole('button') .nth(1) .click(); // 4. Use filter to narrow down await page .getByRole('button') .filter({ hasText: 'Submit' }) .click();

Shadow DOM & iFrames

Shadow DOM

Playwright pierces Shadow DOM automatically!

// No special syntax needed! await page .getByRole('button', { name: 'Submit' }) .click(); // Works even if button is inside shadow-root // Playwright automatically pierces shadow DOM // For specific shadow root navigation await page .locator('my-component') .getByRole('button') .click();

iFrames

Access iFrame elements with frameLocator()

// Get frame by name or URL const frame = page.frameLocator('iframe[name="myframe"]'); // Use locators inside frame await frame .getByRole('button', { name: 'Submit' }) .click(); // Nested frames const innerFrame = frame .frameLocator('iframe#inner'); await innerFrame .getByLabel('Email') .fill('user@example.com');
Shadow DOM = Automatic | iFrames = frameLocator()
