The Problem with Raw AI API Calls

You call the OpenAI API. It works. Then the real problems start.

No Memory

Every API call is stateless. Multi-step workflows (generate → review → prioritise) require you to manually stitch results together.

Text Only

The AI can't read PDFs, query databases, or run Playwright. You must write all the plumbing yourself — every integration from scratch.

Unstructured Output

The AI returns a string. You need a typed TypeScript object. If it formats its answer differently today, your parser breaks.

LangChain solves all three. It provides memory, tool integrations, and structured output parsers — so you build QA AI tools instead of plumbing.

What Is LangChain?

LangChain is a framework for building applications powered by language models.

  • Connects LLMs to external data, tools, and memory
  • Provides composable building blocks — not a black box
  • Works with OpenAI, Anthropic, Gemini, local models
  • First-class TypeScript support
  • Used in production by thousands of companies

Without LangChain:

Write plumbing for memory, output parsing, retries, tool calls, prompt templates — every project from scratch.

With LangChain:

Compose pre-built, tested components. Focus on your QA logic, not infrastructure.

Not a replacement for Playwright — it is the AI brain behind your test tools.

The 6 Core Building Blocks

1. LLM / Chat Model

The AI brain. GPT-4o, Claude, Gemini. LangChain wraps them with a unified interface — swap models without rewriting your app.

2. Prompt Template

Parameterised, reusable prompts. Separate prompt design from code. Keep system and user messages clean and testable.

3. Chain (LCEL)

Compose components using the pipe operator |. Template → Model → Parser — readable, testable pipelines.

4. Memory

Give your AI context across calls. Conversation history, summary memory, vector-based recall. Stateful AI pipelines.

5. Tools

Connect AI to the real world — web search, calculators, APIs, Playwright, databases. The AI decides when to use them.

6. Agent

An AI that reasons about which tools to use and in what order — to solve a goal autonomously. The most powerful pattern.

Part 1

Models, Prompts & Chains

The foundations every QA engineer needs before building AI tools

LLMs vs Chat Models — What's the Difference?

LLM (Completion Model)

Takes a raw text string. Continues it. Good for single-shot generation — write a test case, summarise a bug.

// Input text → continued text const result = await model.invoke( "Write a test case for login:" );

Chat Model (Preferred)

Takes a list of messages (system + human + AI). Preserves roles and context. Works the way ChatGPT works internally.

const messages = [ new SystemMessage("You are a QA expert"), new HumanMessage("Generate test cases") ];

Use ChatOpenAI for all your QA tools. It's the standard for modern AI applications.

Prompt Templates — Reusable, Parameterised Prompts

❌ Without templates:

// Hardcoded — hard to maintain const prompt = `You are a QA expert. Generate 5 test cases for login. Format as JSON.`;

✅ With ChatPromptTemplate:

const template = ChatPromptTemplate.fromMessages([ ["system", "You are a QA expert. Respond in JSON."], ["human", "Generate {count} tests for: {feature}"] ]); // Reuse across any feature await template.format({ count: 5, feature: "login" });
  • Variables {'{feature}'} injected at call time
  • System prompt stays consistent across tests
  • Easy to test the template independently
  • Change one template → all chains updated
  • Shareable across team members

Think of prompt templates like Page Object classes — they centralise what would otherwise be scattered strings.

Output Parsers — Get Typed TypeScript Objects

The AI always returns a string. Output parsers convert it into typed objects you can actually use in your test code.

Define a Zod schema for your output:

const TestCaseSchema = z.object({ title: z.string(), steps: z.array(z.string()), expected: z.string(), priority: z.enum(["High","Medium","Low"]) }); const parser = StructuredOutputParser .fromZodSchema(TestCaseSchema);

Plug into your chain:

const chain = prompt | model | parser; const result = await chain.invoke({ feature: "user login" }); // result is fully typed ✓ console.log(result.title); // string console.log(result.steps); // string[] console.log(result.priority);// "High"|"Medium"|"Low"

Type-safe output

Auto-retry on bad format

LCEL — The LangChain Expression Language

Compose components with | just like Unix pipes. Each component outputs what the next expects.

// Template → Model → Parser: a complete AI pipeline in one line const chain = promptTemplate | chatModel | outputParser; // Invoke with variables const testCases = await chain.invoke({ feature: "password reset", count: 5, format: "JSON" });

Prompt Template

Inject variables into a reusable prompt

Chat Model

Send to GPT-4o, Claude, etc.

Output Parser

Typed TypeScript object

Chains are composable, testable, and readable. You can unit-test each component separately.

Part 2

Memory, Tools & Agents

Give your AI context, capabilities, and the ability to reason

Memory — Give AI Context Across Calls

  • Every AI call is stateless by default — no memory
  • For multi-step QA workflows you need context
  • Generate test cases → Review them → Prioritise
  • Each step needs to "remember" the previous output

Types of Memory:

  • Buffer — stores all messages verbatim
  • Summary — AI summarises old messages to save tokens
  • Vector — semantic recall from a knowledge store
const memory = new BufferMemory({ returnMessages: true, memoryKey: "chat_history" }); const chain = new ConversationChain({ llm: model, memory }); // Turn 1 — generates test cases await chain.call({ input: "Generate tests for login" }); // Turn 2 — AI remembers turn 1 ✓ await chain.call({ input: "Now prioritise those by risk" });

Tools — Connect AI to the Real World

Tools are functions the AI can decide to call. You define what they do. The AI decides when to use them.

Web Search

Look up current docs, CVEs, changelog entries for the app under test

Database Query

Read test data, defect history, requirement tables directly from SQL or API

Playwright Runner

Execute browser actions — the AI can trigger tests and read the results

const runPlaywrightTest = tool( async ({ testName }) => { // actually runs your Playwright test and returns result return await execPlaywright(testName); }, { name: "run_playwright_test", description: "Runs a named Playwright test and returns pass/fail + error", schema: z.object({ testName: z.string() }) } );

Agents — AI That Reasons and Acts

A Chain is a fixed pipeline.

Template → Model → Parser. Same steps, every time.

An Agent is dynamic.

It looks at your goal, decides which tools to use, uses them, observes the result, and repeats until the goal is met.

QA Agent Example:

Goal: "Analyse why the login test failed today and suggest a fix."

The agent: reads logs → searches docs → queries defect DB → generates fix suggestion.

const agent = await createReactAgent({ llm: model, tools: [ readTestLog, searchDocs, queryDefectDB ] }); const result = await agent.invoke({ messages: [new HumanMessage( "Login test failed at 09:14. Analyse and suggest a fix." )] }); console.log(result.messages.at(-1).content); // Root cause + suggested fix

RAG — Retrieval-Augmented Generation

Make AI answer questions from your own test documents and knowledge base

RAG — What It Is and Why QA Engineers Need It

RAG = give the AI access to YOUR documents so it answers from your knowledge, not just its training data.

Load Docs

PDFs, Jira, Confluence, Excel, test reports

Chunk

Split into small, overlapping pieces

Embed

Convert to numerical vectors (semantic meaning)

Retrieve

Find most relevant chunks for the question

Generate

AI answers using retrieved context

QA Use Case 1

Ask AI questions about your requirements doc: "What are the acceptance criteria for checkout?"

QA Use Case 2

Query your defect history: "What bugs occurred most in the payments module last quarter?"

QA Use Case 3

Generate tests from requirements: "Create test cases for every acceptance criterion in section 3.2."

4 Real QA Tools Built with LangChain

 AI Test Case Generator

Takes a feature description (or acceptance criteria) and generates structured, prioritised test cases as typed JSON objects. Uses StructuredOutputParser + Zod schema.

 AI Bug Report Analyzer

Takes raw bug reports and classifies them by severity, module, and likely root cause. Returns structured output you can import directly to Jira or your defect tracker.

 AI Test Data Generator

Generates unlimited realistic, typed test data from a Zod schema. No hardcoded fixtures. Generate edge cases, boundary values, and locale-specific data on demand.

 AI Selector Healer

When a Playwright test fails because a locator is broken, the AI analyses the DOM and suggests alternative locators — no human needed to fix flaky selectors.

Key Takeaways — LangChain for QA

What LangChain gives you:

  • Reusable prompt templates (like Page Objects)
  • Typed outputs via Zod schemas
  • Composable chains with the pipe operator
  • Memory for multi-step conversations
  • Tools that connect AI to Playwright, APIs, DBs

  • RAG to query your own test knowledge base

What to build first:

  • AI Test Case Generator from requirements
  • Bug Report Analyzer and classifier
  • AI Test Data Factory with Zod schemas
  • Playwright Selector Healer agent

Remember:

LangChain is the foundation. Add LangGraph for complex orchestration, LangSmith for observability and evaluation in production.
