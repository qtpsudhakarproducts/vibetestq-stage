The Problem: AI Is a Black Box — Until Now

Without LangSmith, AI pipelines are opaque:

  • You can't see which prompt was used for each call
  • You don't know why the AI gave a wrong answer
  • You can't prove quality improved after a change
  • You can't catch regressions when you update prompts
  • No way to benchmark one model against another

With LangSmith, you get full visibility:

  • Every LLM call traced — input, output, tokens, latency
  • Side-by-side comparison of prompt versions
  • Automated evaluation against golden datasets
  • Regression detection in CI before each deploy
  • Model benchmarks: GPT-4o vs Claude vs Gemini

LangSmith is to AI what test reports and dashboards are to Playwright — it makes quality visible and provable.

Setting Up Tracing — Zero Code Changes Required

Set three environment variables and every LangChain call is automatically traced. No instrumentation code needed.

1. Set environment variables (.env):

# Enable automatic tracing LANGCHAIN_TRACING_V2=true # Your LangSmith API key LANGSMITH_API_KEY=lsv2_pt_... # Project name (groups all runs together) LANGCHAIN_PROJECT=qa-test-generator

2. Run your existing code — no changes:

// Your LangChain code is unchanged const result = await chain.invoke({ feature: "password reset" }); // ✅ Automatically traced in LangSmith

What gets captured automatically:

  • Full input prompt sent to the LLM
  • Full output returned from the LLM
  • Model name, temperature, token count
  • Latency (ms) for each step
  • Token cost (USD) per call
  • Tool calls made by agents
  • Errors and stack traces

Works with LangGraph too

Full execution graph is traced — every node, every edge decision, every state update. See the exact path your graph took.

Datasets, Evaluation & Custom Evaluators

Systematically measure and prove the quality of your AI tools

Datasets — Your Golden Test Suite for AI Quality

A LangSmith dataset is a curated set of inputs + expected outputs. Your AI must produce the right output for each input to pass.

import { Client } from "langsmith"; const client = new Client(); // Create a named dataset const dataset = await client.createDataset( "test-case-generator-v1" ); // Add golden examples await client.createExamples({ inputs: [ { feature: "user login" }, { feature: "password reset" }, { feature: "checkout payment" } ], outputs: [ { minTests: 5, hasPriorityHigh: true }, { minTests: 4, includesExpiry: true }, { minTests: 6, includesDecline: true } ], datasetId: dataset.id });

What makes a good golden dataset:

  • Representative inputs from your domain
  • Verified correct outputs from domain experts
  • Edge cases that are known to be tricky
  • Examples from real past failures
  • At least 20–50 examples per capability

Think of it like Playwright fixtures

Your dataset is your test data. Your evaluator is your assertion. Running evaluation is running your test suite against the AI.

Running Evaluations — Automated AI Quality Checks

// The target: your AI pipeline async function targetPipeline(input) { return await testCaseChain.invoke(input); } // An LLM-based evaluator const evaluator = LangChainStringEvaluator( "criteria", { criteria: { coverage: "Does the output cover happy path and edge cases?", format: "Are test cases in valid JSON with title, steps, expected?" }} ); // Run evaluation against the golden dataset const results = await evaluate( targetPipeline, { data: "test-case-generator-v1", evaluators: [evaluator], experimentPrefix: "gpt4o-v2" } );

What you get back:

  • Score for every example in the dataset
  • Aggregate pass rate across the full dataset
  • Side-by-side comparison across experiments
  • Breakdown: which examples failed and why
  • Token cost and latency for the full eval run

Experiment comparison:

Run the same dataset against "gpt4o-v1" and "gpt4o-v2" (different prompt). LangSmith shows you the delta in quality instantly — no manual comparison.

Custom Evaluators — Write Your Own Scoring Functions

LLM-based evaluators are powerful but imprecise. For QA tools, write deterministic code evaluators that check exactly what matters.

// Custom evaluator: checks test case quality function testCaseQualityEvaluator({ prediction, reference }) { const tests = prediction.testCases; // Must have at least N test cases if (tests.length < reference.minTests) { return { key: "coverage", score: 0, comment: `Only ${tests.length} tests, need ${reference.minTests}` }; } // Must include at least one High priority const hasHigh = tests.some(t => t.priority === "High"); if (reference.hasPriorityHigh && !hasHigh) { return { key: "priority", score: 0, comment: "No High priority test case included" }; } return { key: "quality", score: 1 }; }

Types of evaluators for QA tools:

  • Structural: output has all required fields
  • Schema: output passes Zod validation
  • Coverage: all acceptance criteria mentioned
  • Semantic: AI judge: is this a good test case?
  • Regression: same input → same output
  • Boundary: edge cases are represented

Combine evaluator types

Use a structural evaluator first (fast, deterministic), then an LLM evaluator only for examples that pass the structural check.

CI Integration — Quality Gates for Every Deployment

Run your evaluation suite in GitHub Actions on every PR. Block the merge if AI quality drops below your threshold.

# .github/workflows/ai-eval.yml name: AI Quality Evaluation on: [push, pull_request] jobs: evaluate: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-node@v4 with: { node-version: '20' } - run: npm ci - name: Run AI Evaluations env: OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }} LANGSMITH_API_KEY: ${{ secrets.LANGSMITH_API_KEY }} LANGCHAIN_PROJECT: ci-eval-${{ github.sha }} run: npm run eval - name: Assert Quality Threshold run: | SCORE=$(node scripts/get-eval-score.js) if (( $(echo "$SCORE < 0.85" | bc -l) )); then echo "❌ AI quality below 85% threshold" exit 1 fi echo "✅ AI quality: $SCORE"

What to gate on:

  • Overall pass rate > 85% on golden dataset
  • No regression vs. previous experiment
  • P95 latency < 3 seconds per call
  • Cost per run within budget threshold
