What is MCP — and Why It Matters Now

🎓 Analogy

MCP is the USB-C of AI. Before USB-C, every device had a different cable. MCP gives AI one standard way to connect to any tool — Jira, GitHub, your filesystem, a live browser, Confluence, Slack — all through the same protocol.

❌ Claude without MCP

  • Only knows what you paste into the chat
  • Cannot read your files
  • Cannot browse your application
  • Cannot interact with Jira or GitHub
  • Works in isolation from your real tools

✅ Claude with MCP

  • Reads your project files directly
  • Browses and interacts with your live app
  • Creates Jira tickets, reads GitHub issues
  • Has full context — not just what you paste
  • Acts as a true QA collaborator in your workflow

Industry shift: MCP is now an open standard adopted by OpenAI, Google, and Microsoft — not just Anthropic. It is becoming the universal protocol for AI-tool integration. 2025

AI flags requirements that are untestable, contradictory, or missing acceptance criteria — before anyone writes a single test.

Gherkin Syntax — Feature, Scenario, Given, When, Then

🎓 QA Analogy

Given = precondition (the state before the action). When = the action the user takes. Then = the expected result you are asserting. You have been writing these mentally your whole career — Gherkin just gives them a formal structure.

# Full feature file anatomy Feature: Veg Cart — Add to Cart As a customer I want to add vegetables to my cart So I can proceed to checkout Scenario: Add within quantity limit Given I am on the Veg Cart homepage When I select Carrots and set qty to 5 Then the cart badge shows 5 items And the cart total updates correctly
# Scenario Outline for data-driven Scenario Outline: Quantity limit validation Given I am on the vegetables page When I try to add <quantity> of <veg> Then I should see <message> Examples: | quantity | veg | message | | 5 | Carrot | Added to cart | | 10 | Tomato | Added to cart | | 11 | Potato | Max 10 per item |
Key Gherkin rules

One Feature per file. Multiple Scenarios per feature. And / But extend Given, When, or Then. Scenario Outline runs the same scenario with different data.

Generating .feature Files with AI 🛒 Veg Cart

Prompt pattern that works

Act as a senior QA engineer for Veg Cart. Requirement: "Users can apply a coupon code at checkout. Valid coupons give 10% discount. Invalid coupons show error. Each coupon can only be used once." Generate a Gherkin .feature file covering: happy path, invalid coupon, expired coupon, already-used coupon, and empty coupon field. Use Scenario Outline where applicable.

Common AI mistakes in Gherkin — catch these

  • Generic scenario names — "Test coupon" instead of "Apply valid 10% discount coupon"
  • Missing negative scenarios — happy path only
  • Vague Then steps — "page updates" instead of "discount of ₹45 is shown"
  • Over-specific selectors in steps — steps should describe behaviour, not UI elements

Iterative prompt: After generating, ask — "Review these scenarios. Are any negative paths missing? Are the Then steps specific enough to be automatable?"

🔒 DPDP Act — India 2023 India

The Digital Personal Data Protection Act makes it a legal obligation to protect personal data in India.

  • Never use real customer names or phone numbers in tests
  • Never paste production database records into AI
  • Never share delivery addresses of real users

✅ The rule for Veg Cart testing

  • Generate all user data synthetically with AI
  • Use realistic but entirely fictional names and addresses
  • Scan test data sets for accidentally included PII before committing to repo

Bug Reporting with AI 🛒 Veg Cart

Prompt: rough notes → professional report

Act as a QA engineer writing a Jira bug. Issue found on Veg Cart: When I apply coupon SAVE10 at checkout, the 10% discount is calculated on the subtotal BEFORE delivery charges are added — but our rule is discount should apply to subtotal only, not delivery. Sometimes the total shown is wrong. Write a professional bug report with: Summary, Environment, Steps to Reproduce, Expected Result, Actual Result, Severity, and suggested root cause.

✅ AI-generated output

Summary: Coupon discount applied to delivery charge incorrectly
Severity: High — financial impact
Steps: 1) Add items to cart 2) Proceed to checkout 3) Apply SAVE10 4) Observe total
Expected: 10% discount on subtotal only
Actual: 10% applied to subtotal + delivery
Root cause: Discount calculation function likely receives order total rather than subtotal as input

Root Cause Analysis & Defect Pattern Analysis Updated

Root Cause Analysis with AI

Give AI the error message, the logs, the steps, and the expected vs actual behaviour — it suggests probable root causes ranked by likelihood.

Veg Cart example

"Cart total shows ₹0 after applying expired coupon. Error log: TypeError: Cannot read property 'value' of undefined. Steps: add items → apply EXPIRED coupon → view total. What are the likely root causes?"

Defect Clustering New

AI identifies that multiple separate bug reports are symptoms of the same underlying root cause.

3 separate Jira tickets:
BUG-12: Cart total wrong with SAVE10
BUG-19: Free delivery coupon breaks total
BUG-23: Bulk discount shows negative total

AI identifies: All three share the same root cause — discount calculation function receives incorrect input parameter

Bug Report Quality Scoring New

AI assesses whether a bug report has sufficient information for a developer to action it — flags missing environment details, vague steps, or unclear expected results before you submit.

Prompt Versioning & Skills Evolution New Practice

🎓 Analogy

Prompts are not throwaway chat messages. They are assets — just like test cases. You version test cases. You review and improve them. Do the same with prompts.

How Skills.md evolves across the program

LevelWhat gets added
Level 1Basic QA role, prompt preferences, output formats
Level 2Veg Cart context, MCP rules, Gherkin standards, data conventions
Level 3TypeScript conventions, POM structure, Playwright patterns, CI rules

Prompt versioning in practice

  • Save working prompts to the /prompts folder
  • Name them descriptively: gherkin-from-requirement-v2.md
  • When you improve a prompt, commit the change — just like updating a test case
  • Add a comment: what changed and why
Why this matters

A prompt that generated great Gherkin last week should be reproducible. If you can't find it, you'll spend 30 minutes recreating it. Version it instead.
