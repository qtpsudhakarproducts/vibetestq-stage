Depth-Based Answer Calibration

Basic  ·  Intermediate  ·  Advanced

Phase 2 · In the Interview

Same Question. Three Expected Depths.

Answering at the wrong depth — too shallow or too deep — is an instant red flag.

1
Basic Depth (Ch 7) · CLI & codegen · Accessible locators · Page Object Model basics · Git & local reports
2
Intermediate Depth (Ch 8) · Config & fixtures · Shadow DOM piercing · API specs · Cucumber BDD · Suite tagging
3
Advanced Depth (Ch 9) · Playwright MCP · Agent rules (SKILL.md) · CI sharding · Enterprise self-healing · Multi-repo
Phase 2 · In the Interview

"How do you implement Page Object Model?" — 3 Depths

1
Basic Depth: "Classes with locators & helper methods"
"I create page object classes, defining locator elements as properties and writing basic helper methods to execute actions."
2
Intermediate Depth: "Inheritance, encapsulation & direct instantiation"
"We implement a BasePage with shared elements, inherit it across pages, encapsulate locators via constructors, and initialize them directly in tests."
3
Advanced Depth: "Custom fixtures & zero-instantiation tests"
"Create a custom test fixture extending Playwright's base test to auto-instantiate and inject page objects, completely removing page setup redundancy from spec files."

Chapter 6

How to Answer

Confidence  ·  Structure  ·  Never silent

Phase 2 · In the Interview

The 3-State Answer Model

I Know It

Answer instantly. Add a specific project example — never a generic textbook definition.

I'm Not Sure

"I've seen this but haven't used it directly — from what I know, it works by..."

I Don't Know

Say: "I haven't used it directly, but I'd approach it by..." then reason through your thinking steps out loud. Never go silent.

What to Do

Add Project Context
Back up claims with measurable outcomes
Use Domain Vocabulary
Mention BrowserContext, trace, fixtures, MCP

What to Avoid

Avoid Generic Sites
Don't say "Login to Google" as your example
Don't Sit Silent
Explain how you'd debug or research the issue

"Knowing the answer is 50%. Showing you understand the concept — and why it works — is the other 50% that gets you the offer."

Chapter 11

The 4 Feedback Levels

Good  →  Very Good  →  Excellent  →  Outstanding

Phase 3 · How You Are Evaluated

What Each Level Requires

FeedbackWhat You DemonstratedOutcome
GoodBasics correct. Dimension 1 only. No standout moments. Maybe — if no stronger candidate
Very GoodSolid on their stack (Dim 2). Real examples. Correct mastery depth. Likely selected — strong contender
ExcellentAll 3 dimensions. Industry trends fluent. GitHub portfolio verifies skills. Selected — priority candidate
OutstandingAll above + BDD, AI Agents, STANDARDS.md. Strategic questions. Selected fast — stronger offer likely

  The Outstanding gap: Outstanding candidates talk about the system — STANDARDS.md, agent workflows, CI sharding, BDD ownership. Good candidates talk about individual tests. One level of abstraction higher.
