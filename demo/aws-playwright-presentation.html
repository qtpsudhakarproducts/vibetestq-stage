EC2: Your Virtual Computer in the Cloud

EC2 = Elastic Compute Cloud - A virtual computer you rent from AWS

What's Inside an EC2 Instance?

CPU: Processing power to run your tests

RAM: Memory for browsers and test execution

Storage: Hard drive space for code and reports

Network: Internet connection for accessing websites

OS: Ubuntu Linux operating system

Key Feature: Start/stop anytime - pay only when running!

Choosing the Right EC2 Instance

t2.micro (Recommended for Learning)

1 vCPU, 1 GB RAM → Perfect for basic tests → FREE TIER

t3.small

2 vCPUs, 2 GB RAM → Better performance → ~$0.02/hour (~$15/month)

t3.medium

2 vCPUs, 4 GB RAM → Multiple parallel tests → ~$0.04/hour (~$30/month)

c5.large (Production)

2 vCPUs, 4 GB RAM, optimized CPU → Large test suites → ~$0.085/hour (~$62/month)

Pro Tip: Start with t2.micro (free), upgrade as needed. Stop instance when not testing!

Security Groups: Your Virtual Firewall

Security Group = Rules that control who can access your EC2 instance

Nightclub Bouncer Analogy

Security Group = Bouncer at the door

• Bouncer checks list: Only approved IPs can enter
• Port 22 (SSH): The door for remote access
• Your IP only: Like being on the VIP list
• Block everyone else: Uninvited guests can't get in

Best Practice: Allow SSH (Port 22) only from YOUR IP address (/32)

SSH: Your Secure Remote Connection

SSH = Secure Shell - Encrypted connection to control remote computers

How It Works

1. Key Pair: Like a lock and key
2. Private Key: Stays on your laptop (secret)
3. Public Key: Goes on EC2 instance
4. Connection: Only matching key works

Why Secure?

Encrypted traffic
No passwords needed
Can't be stolen easily
Prevents unauthorized access

# Connect to EC2 instance ssh -i ~/.ssh/playwright-key.pem ubuntu@54.123.45.67

The Complete Setup Journey

1 Create AWS Account → Sign up and verify identity

2 Install AWS CLI → Command-line tool to control AWS

3 Configure Credentials → Add your access keys

4 Create SSH Key Pair → Generate secure access keys

5 Create Security Group → Set firewall rules (Port 22)

6 Launch EC2 Instance → Start Ubuntu 24.04 virtual machine

7 Connect via SSH → Remote login to your instance

8 Install Node.js → Setup test environment

9 Install Playwright → Add test framework

10 Run Tests → Execute your test suite in the cloud!

Time Required: 2-3 hours for first-time setup

Setting Up Playwright on EC2

After connecting via SSH, run these commands:

# Update system packages sudo apt update && sudo apt upgrade -y # Install Node.js 20 LTS curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - sudo apt install -y nodejs # Verify installation node --version # Should show v20.x npm --version # Install Playwright system dependencies sudo npx playwright install-deps # Create test project mkdir playwright-tests && cd playwright-tests npm init -y npm install -D @playwright/test # Install Playwright browsers npx playwright install

Important: Always run playwright install-deps first on fresh instances!

Running Your First Cloud Test

Create a simple test file on EC2:

# Create test directory and file mkdir tests cat > tests/demo.spec.js << 'EOF' const { test, expect } = require('@playwright/test'); test('AWS cloud test', async ({ page }) => { await page.goto('https://playwright.dev/'); const title = await page.title(); expect(title).toContain('Playwright'); console.log('✅ Test running on AWS EC2!'); console.log('📍 Page title:', title); }); EOF # Run the test npx playwright test # Run with headed mode to verify (uses Xvfb) npx playwright test --headed

Success! Your test is now running on AWS cloud infrastructure 🎉

Managing AWS Costs

Cost-Saving Tips

  • Stop instances: Don't leave EC2 running when not testing (save 100% on compute)
  • Use t2.micro: Free Tier eligible for 750 hours/month
  • Set billing alerts: Get notified before spending money
  • Use spot instances: Up to 90% cheaper for non-critical tests
  • Auto-shutdown: Schedule EC2 to stop after hours
  • Monitor usage: Check AWS Cost Explorer monthly
# Stop EC2 instance (from your local machine) aws ec2 stop-instances --instance-ids i-1234567890abcdef0 # Start again when needed aws ec2 start-instances --instance-ids i-1234567890abcdef0 # Terminate (delete permanently) when done aws ec2 terminate-instances --instance-ids i-1234567890abcdef0

Common Issues & Quick Fixes

❌ "Permission denied (publickey)"

✅ Run chmod 400 ~/.ssh/playwright-key.pem to fix permissions

❌ "Connection timed out"

✅ Check security group allows YOUR IP on Port 22. Your IP may have changed!

❌ "Executable doesn't exist at chromium path"

✅ Run sudo npx playwright install-deps and npx playwright install

❌ Tests fail on EC2 but pass locally

✅ Increase timeouts, check network latency, ensure headless mode configured

❌ "Instance stopped unexpectedly"

✅ Check if you exceeded Free Tier limits. Verify billing alerts are set.

AWS Security Checklist

Critical Security Practices

✅ DO:

  • Use SSH keys (never passwords)
  • Restrict security groups to YOUR IP only (/32)
  • Store AWS credentials in environment variables
  • Enable MFA (Multi-Factor Authentication)
  • Use IAM roles instead of root account
  • Rotate access keys every 90 days
  • Set up CloudWatch billing alerts
  • Keep EC2 instances updated (apt update)

❌ DON'T:

  • Commit AWS keys to Git repositories
  • Open Port 22 to 0.0.0.0/0 (entire internet)
  • Share SSH private keys via email/Slack
  • Use root account for daily operations
  • Leave instances running 24/7 unnecessarily
  • Disable security warnings or updates
