Act 2

The Missing Piece

30 years of the same gap · The sharpest insight in this session

Documentation Change vs Code Change

REQUIREMENT CHANGES

Which tests cover REQ-001?

Which test cases need updating?

We could do this — imperfectly — for 30 years ✅
CODE CHANGES

Which requirements does authenticateUser() implement?

What breaks downstream if this function changes?

We could NEVER do this automatically ❌

These are completely different questions — the first had tools for 30 years — the second never did

Has anyone been surprised by a production bug that traced back to something nobody realised had changed downstream?

Type 3 — The Parallel Stream Model

Dev and QA start at the same moment. Neither waits. Both intersect at defined synchronisation points.

 DEV STREAM — Sprint Day 1
↓

↓

 QA STREAM — Sprint Day 1
↓

↓

 Dev explores what they built. QA explores blind to dev. QA finds what dev could not see. Never skip independent QA exploration.

Type 4 & Type 5

Type 4 — Agentic

  • Specialised agents handle entire phases
  • Planner → Generator → Execution → Healer → Observability
  • QA governs the quality system

Type 5. Legal liability without human sign-off.

Type 5 — Regulated

  • AI accelerates everything
  • Every artifact requires human sign-off
  • Audit trail mandatory
  • Banking, healthcare, fintech, pharma

Why Type Matters

The workflow must match the SDLC type. Mismatch = failure. Right workflow for the right type.

Act 6

Real Failure Examples

6 failure patterns · Know them before they happen

Failures 1, 2, 3

Failure 1 — AI Without Understanding — 200 tests pass ✅. International checkout fails in production. Tests never covered non-ASCII. Trap: Test count ≠ Coverage. Fix: WF11 every sprint.

Failure 2 — Developer Blind Spots — Dev explores their feature. QA skips independent exploration. Coupon + subscription = broken in production. Trap: Dev blind spots match their implementation. Fix: WF5 non-negotiable.

Failure 3 — Sprint Pressure Corrupts — Friday deadline. Dev: “tested happy path.” QA: 3 generic test cases. All green ✅. 6 production bugs. Trap: Process appears followed. Quality not delivered. Fix: Feature done = exploration thorough.

Failures 4, 5, 6

Failure 4 — Unstructured Capture — Sprint 1: great JSON ✅ · Sprint 5: free text ⚠️ · Sprint 8: nothing ❌. 50 files of noise. No compound intelligence. Trap: Volume grows. Signal degrades. Fix: Define JSON structure before Sprint 1.

Failure 5 — False Green Confidence — 12 new features. Self-healing keeps 200 tests green ✅. New features: zero coverage. Production regression. Trap: Green feels like good coverage. Fix: WF11 mandatory every sprint.

Failure 6 — QA Skills Atrophy — Full automation 6 months. QA only reviews dashboards. Complex race condition. Agents cannot diagnose. QA skills rusty. 3-day incident. Trap: Oversight feels productive. Skills erode silently. Fix: Manual exploration every sprint.

Implement 13 workflows and ignore these 6 — you will hit at least three in your first six sprints.
