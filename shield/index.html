A heal, start to finish

Recover the action.
Keep the business check.

Shield helps a click, a fill or a check find the element it meant. It never changes what a test expects: your assertions still decide whether the application is right.

01 · During the run

The button was renamed in the last deploy. Shield found it by what it is for, tried it on the live page, and the test went on.

02 · In the code

Runtime healing never edits your files. apply-heals does: where the locator is defined, with a report ready for the pull request.

03 · Proven

The tests of the changed lines run again with healing off. A fix counts only when its test passes on its own; the next CI run marks it Fixed.

A heal that needs a look

Shield says when it is not sure.

A heal is marked Needs a look when a person should check it before the change is merged: the new locator fits more than one element, finds the element by the text or position near it, or the action had to be forced. Each one says why and how to check it.

A heal that did not work says why, and the test fails as it would without TAMASH.

Maintenance

For the tests that still fail.

Healing fixes locators. Maintenance, run from your AI coding assistant with the TAMASH skill, looks at each test that still fails and decides why.

Locator drift

The locator is fixed in the code and verified with healing off.

An intended change

The test is updated only with evidence the change was intended, such as a ticket or a pull request, or with your approval.

A suspected defect

The test is left as it is and the defect is reported for a person. Flaky tests, test data and the environment are reported the same way.

Product code is never changed, and a test is never weakened to make it pass: no broader selectors, no deleted assertions, no longer timeouts.

In your workflow

Locally and in CI, the same way.

On a laptop

Sign in once with npx tamash-runsights login and approve the machine in the browser. Every run then heals as it goes and reaches RunSights in your name.

In CI

One secret, TAMASH_ACCESS_TOKEN, set to a service token of the project. Healing works the same way, and the pull request carries the fixes.

Works with your tests as they are

  • Playwright Test: two lines in playwright.config. Your specs keep importing from @playwright/test.
  • Cucumber.js: two lines in the profile. Hooks and step definitions do not change.
  • A locator described with .describe('Pay now button') heals best.

What is sent for a heal

  • The action, the element's description, the error and the accessibility snapshot of the page. TAMASH uses it to answer and does not keep it.
