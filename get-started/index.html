Get started

Ten minutes from the token
to the first run.

Your trial gives you an npm token and a project key. Nothing else changes in how you run Playwright or Cucumber.

No trial yet? Request one ↗, or book a demo.

  1. 01

    Install

    The packages are restricted. Put the token you received in NPM_TOKEN and let npm read it from an .npmrc in the project root, which is safe to commit because it holds the variable's name, not its value.

  2. 02

    Set the project up

    One command adds the RunSights reporter to your Playwright config, sets an actionTimeout when there is none, switches your test files to import from Shield, and leaves a place for the key in .env. It shows every change and asks before writing; --dry-run only shows.

    Then copy the project key from Projects in the portal into .env. The key says which project; it is not a secret in the sense of a password, but keep it out of public repositories.

  3. 03

    Sign your machine in

    The key says which project, a token says who. On a laptop, sign in once from the browser; the machine gets its own token in your name, and a run from it shows under your name in RunSights.

    In CI, there is nobody to approve a machine, so an Org Admin or a project admin makes a service token for the project in the portal and the pipeline carries it as a secret named TAMASH_ACCESS_TOKEN, next to TAMASH_LICENSE_KEY. A service token works only in a pipeline; a personal token works only on a person's machine.

  4. 04

    Run as usual

    Nothing in your command line changes.

    Cucumber.js (v8 and later) uses the same packages through a formatter. Add it beside your console formatter in cucumber.js; the options go under formatOptions.tamashDashboard.

  5. 05

    Check the setup and look at the result

    npx tamash-shield doctor confirms the service accepts your key and answers within your actionTimeout, and points out locators that would heal better with a .describe() label. Then open the portal:

    RunSights

    The run you just sent, with every test and attempt, where it ran and who ran it. Trends build from the second run.

    Shield

    The heals of the run, by test, with the locator that broke and the one that worked, and anything that needs a look.

    Forge

    With Forge, the same runs also count toward the test cases and cycles they are linked to.
