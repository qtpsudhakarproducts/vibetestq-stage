test.describe — Grouping and Nesting

import { test, expect } from '@playwright/test'; // Top-level describe = feature or page test.describe('User Authentication', () => { // Nested describe = sub-scenario test.describe('Login', () => { test('valid credentials', async ({ page }) => { /* ... */ }); test('invalid credentials', async ({ page }) => { /* ... */ }); test('empty fields validation', async ({ page }) => { /* ... */ }); }); test.describe('Register', () => { test('successful registration', async ({ page }) => { /* ... */ }); test('duplicate email error', async ({ page }) => { /* ... */ }); }); test.describe('Logout', () => { test('logout from header', async ({ page }) => { /* ... */ }); }); }); // describe.configure — control parallelism per suite test.describe.configure({ mode: 'serial' }); // run these in order test.describe.configure({ mode: 'parallel' }); // run concurrently (default)

Hooks: Setup and Teardown

test.describe('Shopping Cart', () => { // runs once before all tests in this describe block test.beforeAll(async ({ browser }) => { // create shared state, seed test database console.log('Suite starting...'); }); // runs before EACH test — most common hook test.beforeEach(async ({ page }) => { await page.goto('/shop'); await page.getByRole('button', { name: 'Login' }).click(); await page.getByLabel('Email').fill('test@example.com'); await page.getByLabel('Password').fill('Test1234!'); await page.getByRole('button', { name: 'Sign in' }).click(); await expect(page).toHaveURL(/shop/); }); // runs after each test (cleanup) test.afterEach(async ({ page }) => { await page.getByRole('button', { name: 'Clear cart' }).click(); }); // runs once after all tests test.afterAll(async () => { // cleanup test data, close shared connections }); test('add item to cart', async ({ page }) => { /* already logged in */ }); test('remove item from cart', async ({ page }) => { /* already logged in */ }); });

Test Annotations: Tags and Metadata

// Tag tests with @tag in the title — used with --grep filtering test('login with valid creds @smoke @critical', async ({ page }) => {}); test('advanced search filters @regression', async ({ page }) => {}); test('export report as PDF @regression @slow', async ({ page }) => {}); // Built-in annotations test('new feature in progress', async ({ page }) => { test.skip(); // skip this test entirely }); test('known flaky on Safari', async ({ page, browserName }) => { test.fixme(browserName === 'webkit'); // mark as fixme — runs but expected to fail }); test('only run this for now', async ({ page }) => { test.only(); // only this test runs in the file — REMOVE BEFORE COMMIT }); // Conditional skip test('Linux-only test', async ({ page }) => { test.skip(process.platform !== 'linux', 'Linux only'); }); // Add structured info to test report test('upload file', async ({ page }) => { test.info().annotations.push({ type: 'JIRA', description: 'QA-1234' }); test.info().attachments.push({ name: 'screenshot', path: 'shot.png', contentType: 'image/png' }); });

Filtering Tests with --grep

CLI Filter Commands

npx playwright test --grep @smoke npx playwright test --grep @critical npx playwright test --grep "@smoke|@critical" npx playwright test --grep-invert @slow npx playwright test --grep @regression # Run specific file npx playwright test login.spec.ts # Run by test name pattern npx playwright test -g "login"

Tag Strategy

  • @smoke — 5–15 critical path tests, runs per deploy
  • @regression — full suite, runs nightly
  • @sanity — post-deploy validation
  • @slow — excluded from fast pipelines
  • @api — API-only tests subset

Define your tagging strategy in the team wiki and enforce it in CI pipeline configs. Consistent tagging = effective filtering.

Test File Naming and Folder Structure

tests/ auth/ login.spec.ts register.spec.ts logout.spec.ts shop/ product-search.spec.ts cart.spec.ts checkout.spec.ts admin/ user-management.spec.ts reports.spec.ts api/ auth-api.spec.ts products-api.spec.ts visual/ homepage.spec.ts pages/ # Page Objects LoginPage.ts CartPage.ts fixtures/ auth.fixtures.ts # Custom fixtures tests/fixtures/ # Test data files users.json products.csv

File Naming Rules

  • Always end with .spec.ts
  • Use kebab-case: user-login.spec.ts
  • One feature per spec file
  • Group by feature/module in folders

Structure tests to match the app's navigation hierarchy. Testers and devs can find tests intuitively.

Session 13 Recap

Organization Patterns

  • test.describe() — group by feature
  • Nested describe for sub-scenarios
  • beforeEach — shared setup per test
  • beforeAll / afterAll — suite-level setup
  • File structure mirrors app structure

Annotations and Control

  • @smoke, @regression tags via test title
  • --grep filters on CLI and in CI
  • test.skip(), test.fixme(), test.only()
  • Conditional skips with platform checks
  • test.info() for attachments and JIRA links
