JavaScript Data Types

// Primitives — stored by value const name = "VibeTestQ"; // string const count = 42; // number const price = 19.99; // number (no separate float type) const isLoggedIn = true; // boolean const nothing = null; // null — intentional absence const notAssigned = undefined; // undefined — not yet assigned // Reference types — stored by reference const user = { name: "Admin", role: "admin" }; // object const tags = ["smoke", "regression", "login"]; // array const greet = (name) => `Hello ${name}`; // function // Type checking typeof "hello" // "string" typeof 42 // "number" typeof true // "boolean" typeof null // "object" -- famous JS bug, exists for legacy reasons typeof undefined // "undefined" typeof {} // "object" typeof [] // "object" -- use Array.isArray() instead Array.isArray([]) // true

Type Coercion — The JS Traps

Loose Equality == (Dangerous)

// JS tries to convert types first 0 == false // true! "" == false // true! null == undefined // true! "5" == 5 // true! // This breaks assertions expect(count == "5") // might pass unexpectedly

Strict Equality === (Safe)

// No type conversion 0 === false // false ✓ "" === false // false ✓ null === undefined // false ✓ "5" === 5 // false ✓ // Playwright's expect() uses strict equality expect(count).toBe(5); // passes only for number 5 expect(name).toBe("Admin"); // exact string match

Rule: Always use === for comparisons. Never ==. Playwright's toBe() already does this for you.

Three Ways to Write Functions

// 1. Function Declaration — hoisted, available before it's defined function login(user, pass) { return `Logging in ${user}`; } // 2. Function Expression — not hoisted, assigned to variable const logout = function() { return "Logged out"; }; // 3. Arrow Function — concise, lexical this (MOST USED in Playwright) const navigate = async (page, url) => { await page.goto(url); }; // Immediately Invoked Function Expression (IIFE) // Used in Playwright's browser.evaluate() const pageTitle = await page.evaluate(() => document.title); // Function with default parameters + rest params const buildUrl = (base, path = "/", ...params) => { const query = params.join("&"); return `${base}${path}?${query}`; };

In Playwright tests, you will see arrow functions everywhere. Declarations are used in page object methods.

Working with Objects

// Creating test data as objects const testUser = { username: "admin", password: "Admin1234!", role: "admin", fullName: "Admin User" }; // Accessing properties console.log(testUser.username); // dot notation console.log(testUser["password"]); // bracket notation (dynamic keys) // Destructuring — clean way to extract multiple properties const { username, password, role } = testUser; // Adding / modifying properties testUser.email = "admin@test.com"; testUser.role = "superadmin"; // Object methods — Object.keys(), Object.values(), Object.entries() Object.keys(testUser); // ["username", "password", "role", "fullName", "email"] Object.values(testUser); // ["admin", "Admin1234!", ...] Object.entries(testUser); // [["username","admin"], ["password","Admin1234!"], ...] // Spread to clone / merge const updatedUser = { ...testUser, role: "viewer" }; // non-mutating update

Arrays — Test Data Collections

// Test data arrays const credentials = [ { user: "admin", pass: "Admin123" }, { user: "viewer", pass: "View123" } ]; // Access by index (0-based) credentials[0].user; // "admin" // Iterate with forEach credentials.forEach(cred => { console.log(`Testing login for ${cred.user}`); }); // Transform with map const usernames = credentials.map(c => c.user); // ["admin", "viewer"] // Filter const admins = credentials.filter(c => c.user === "admin"); // Find single item const adminCred = credentials.find(c => c.user === "admin"); // Check membership const hasAdmin = credentials.some(c => c.user === "admin"); // true const allHavePass = credentials.every(c => c.pass.length > 5); // true // Spread — add without mutating const moreCreds = [...credentials, { user: "manager", pass: "Mgr123" }];

Conditional Logic in Test Code

if / else / else if

const role = "admin"; if (role === "admin") { await page.goto("/admin"); } else if (role === "manager") { await page.goto("/manager"); } else { await page.goto("/dashboard"); } // Ternary — one-liner conditionals const url = role === "admin" ? "/admin-panel" : "/user-dashboard";

switch / Logical Operators

switch (environment) { case "prod": baseURL = "https://app.com"; break; case "staging": baseURL = "https://staging.app.com"; break; default: baseURL = "http://localhost:3000"; } // Logical AND — short-circuit isLoggedIn && await page.click('#logout'); // Nullish coalescing const retries = opts?.retries ?? 2;

Loops — Iterating Test Data

const testScenarios = ["login", "search", "checkout", "logout"]; // for...of — iterating arrays (PREFERRED in tests) for (const scenario of testScenarios) { console.log(`Running: ${scenario}`); } // for...in — iterating object keys const config = { browser: "chromium", headless: true }; for (const key in config) { console.log(`${key}: ${config[key]}`); } // Classic for loop — when you need the index for (let i = 0; i < testScenarios.length; i++) { console.log(`Test ${i + 1}: ${testScenarios[i]}`); } // while — condition-based loops let attempts = 0; while (attempts < 3) { const result = await tryLogin(page); if (result.success) break; attempts++; } // Playwright: test.for() replaces manual loops for data-driven tests // (covered in Session 17)

In modern Playwright, for...of is used inside helper methods. Tests use test.for() for data-driven scenarios.

Error Handling: try / catch / finally

// Basic try/catch async function loginSafely(page, user, pass) { try { await page.fill('#username', user); await page.fill('#password', pass); await page.click('#login'); return { success: true }; } catch (error) { console.error(`Login failed: ${error.message}`); return { success: false, error: error.message }; } finally { // Always runs — use for cleanup console.log('Login attempt complete'); } } // Custom Error classes class TestSetupError extends Error { constructor(message, context) { super(message); this.name = 'TestSetupError'; this.context = context; } } // Throwing errors function validateConfig(config) { if (!config.baseURL) { throw new TestSetupError('baseURL is required', config); } }

Playwright catches errors automatically and shows them in traces. Use try/catch in helpers for graceful fallbacks.

Writing Reusable Test Helpers

// helpers/url.ts export const buildUrl = (base: string, path: string): string => { return `${base.replace(/\/$/, '')}${path}`; }; // helpers/date.ts export const formatDate = (date: Date): string => { return date.toISOString().split('T')[0]; // YYYY-MM-DD }; export const addDays = (date: Date, days: number): Date => { const result = new Date(date); result.setDate(result.getDate() + days); return result; }; // helpers/random.ts export const randomEmail = (): string => { const id = Date.now(); return `test.${id}@vibetestq.com`; }; export const randomString = (length = 8): string => { return Math.random().toString(36).substring(2, 2 + length); }; // Usage in tests const email = randomEmail(); // "test.1718400000000@vibetestq.com" const today = formatDate(new Date()); // "2025-07-01"

Scope & Closures (Brief Overview)

Block Scope with const/let

// Each block creates a new scope test.describe('Login Suite', () => { const SUITE_CONFIG = { timeout: 30000 }; // Scoped to this describe block test.beforeEach(async ({ page }) => { const loginUrl = '/login'; // Scoped to beforeEach await page.goto(loginUrl); }); test('admin login', async ({ page }) => { const username = 'admin'; // Scoped to this test only // SUITE_CONFIG is accessible here (closure) console.log(SUITE_CONFIG.timeout); // 30000 }); });

Closures are why Playwright fixtures work — the fixture function "closes over" the page context and makes it available inside the test callback.

Putting It All Together — A Real Helper

// utils/test-helpers.ts import { Page } from '@playwright/test'; export interface LoginCredentials { username: string; password: string; } export async function performLogin( page: Page, credentials: LoginCredentials ): Promise<boolean> { try { await page.getByLabel('Username').fill(credentials.username); await page.getByLabel('Password').fill(credentials.password); await page.getByRole('button', { name: 'Login' }).click(); // Wait for dashboard to confirm successful login await page.waitForURL('**/dashboard**', { timeout: 10000 }); return true; } catch (error) { console.error(`Login failed for ${credentials.username}: ${error.message}`); return false; } }

Notice: interface, async/await, arrow within, try/catch, return type — all the patterns from this session, combined.
