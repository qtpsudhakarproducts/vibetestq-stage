Node.js npm Project Anatomy

What is Node.js?

Node.js = JS outside the browser

  • V8 JavaScript engine + OS APIs wrapped together
  • Lets JavaScript run on servers, scripts, CLI tools
  • Non-blocking I/O — handles files, networks efficiently
  • Built-in modules: fs, path, http, os

Why Playwright Needs Node.js

  • Playwright is a Node.js package
  • Test runner executes in Node.js process
  • Browser launch + control happens via Node.js
  • All npm packages are managed via Node.js

Node.js is not optional — it's the runtime that runs your Playwright tests. Use LTS (Long Term Support) version in projects.

Essential Node.js & npm Commands

# Check installed versions node --version # v22.x.x (LTS) npm --version # 10.x.x # Initialize a new project (creates package.json) npm init -y # Install Playwright (and browsers) npm init playwright@latest # Interactive wizard # OR manually: npm install --save-dev @playwright/test npx playwright install # Download browser binaries # Install a package npm install dotenv # production dependency npm install --save-dev typescript ts-node # dev dependency # Run scripts defined in package.json npm test # runs "test" script npm run test:headed # runs custom script # List installed packages npm list --depth=0 # Update packages npm update npm outdated # show packages with newer versions

Always use --save-dev for test tools. They shouldn't be in production dependencies.

package.json — The Project Manifest

{ "name": "my-playwright-framework", "version": "1.0.0", "description": "End-to-end test automation with Playwright", "scripts": { "test": "npx playwright test", "test:headed": "npx playwright test --headed", "test:ui": "npx playwright test --ui", "test:debug": "npx playwright test --debug", "test:report": "npx playwright show-report", "test:smoke": "npx playwright test --grep @smoke", "lint": "eslint . --ext .ts", "typecheck": "tsc --noEmit" }, "devDependencies": { "@playwright/test": "^1.52.0", "typescript": "^5.4.0", "dotenv": "^16.4.0" }, "engines": { "node": ">=20.0.0" } }

The scripts section is your command hub. Define all test run modes here so the team uses consistent commands.

Environment Variables — Secrets Management

.env file (never commit!)

# .env BASE_URL=https://demo.app ADMIN_USER=admin ADMIN_PASS=Admin1234! API_KEY=secret-key-here
# .env.example (commit this!) BASE_URL= ADMIN_USER= ADMIN_PASS= API_KEY=

Using in playwright.config.ts

import { defineConfig } from '@playwright/test'; import dotenv from 'dotenv'; dotenv.config(); export default defineConfig({ use: { baseURL: process.env.BASE_URL || 'http://localhost:3000', }, });

Add .env to .gitignore. Never hardcode credentials in code.

Essential .gitignore for Playwright Projects

# Dependencies node_modules/ # Playwright outputs test-results/ # screenshots, videos, traces playwright-report/ # HTML report .playwright/ # TypeScript compiled output dist/ *.js.map # Environment secrets .env .env.local .env.production # OS files .DS_Store Thumbs.db # IDE .vscode/settings.json # ok to commit extensions, not settings .idea/

The most important: node_modules/ and .env. Never commit these. Run npm install to restore node_modules from package.json.

Node.js Built-in Modules Useful for Testing

import * as path from 'path'; import * as fs from 'fs'; // path — cross-platform file paths const downloadsDir = path.join(__dirname, '..', 'downloads'); const configPath = path.resolve('./playwright.config.ts'); path.basename('/tests/login.spec.ts'); // "login.spec.ts" path.extname('report.json'); // ".json" // fs — file system operations const data = fs.readFileSync('./test-data/users.json', 'utf-8'); const users = JSON.parse(data); // Write test artifacts fs.writeFileSync('./output/results.json', JSON.stringify(results, null, 2)); // Check if directory exists if (!fs.existsSync('./screenshots')) { fs.mkdirSync('./screenshots', { recursive: true }); } // Async file operations (prefer in helpers) import { readFile, writeFile } from 'fs/promises'; const content = await readFile('./data.json', 'utf-8');

You'll use path.join constantly in fixtures to locate test data files relative to the project root.

Running Your First Playwright Test

# 1. Create project and install Playwright mkdir my-pw-project && cd my-pw-project npm init playwright@latest # Choose: TypeScript, tests/ folder, GitHub Actions: Yes # 2. Run the generated example tests npx playwright test # headless, all browsers npx playwright test --headed # watch browser open npx playwright test --project=chromium # one browser only # 3. View the HTML report npx playwright show-report # 4. Run in interactive UI mode npx playwright test --ui # 5. Run a specific file npx playwright test tests/example.spec.ts # 6. Run with tag filter (requires @tag in test names) npx playwright test --grep "@smoke" # 7. Run in debug mode (opens Playwright Inspector) npx playwright test --debug

npx playwright test --ui is the best way to develop tests interactively. Use it daily during development.
