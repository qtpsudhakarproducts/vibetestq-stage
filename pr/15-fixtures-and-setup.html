What Are Fixtures?

Built-in Fixtures

  • page — isolated Page per test
  • context — BrowserContext per test
  • browser — shared Browser
  • request — APIRequestContext
  • browserName — "chromium"|"firefox"|"webkit"

Why Custom Fixtures?

  • Replace repetitive beforeEach login code
  • Inject page objects automatically
  • Share test data and configurations
  • Auto teardown after test
  • Composable — fixtures can use other fixtures

Think of fixtures as dependency injection for tests. Instead of calling new LoginPage(page) in every test, fixtures provide it automatically.

Creating Custom Fixtures

// fixtures/pages.fixtures.ts import { test as base } from '@playwright/test'; import { LoginPage } from '../pages/LoginPage'; import { DashboardPage } from '../pages/DashboardPage'; import { CartPage } from '../pages/CartPage'; // Declare the types of fixtures type PageFixtures = { loginPage: LoginPage; dashboardPage: DashboardPage; cartPage: CartPage; }; // Extend the base test with our custom fixtures export const test = base.extend<PageFixtures>({ loginPage: async ({ page }, use) => { const loginPage = new LoginPage(page); await use(loginPage); // provide fixture to test // teardown code here (optional) }, dashboardPage: async ({ page }, use) => { await use(new DashboardPage(page)); }, cartPage: async ({ page }, use) => { await use(new CartPage(page)); }, }); export { expect } from '@playwright/test';

Using Fixtures in Tests

// tests/login.spec.ts import { test, expect } from '../fixtures/pages.fixtures'; // Always import from your fixtures file, not @playwright/test directly test.describe('Login', () => { test('valid login', async ({ loginPage, dashboardPage }) => { await loginPage.navigate(); await loginPage.login('admin@test.com', 'Admin123!'); await expect(dashboardPage.welcomeMessage).toBeVisible(); }); test('shows error for wrong password', async ({ loginPage }) => { await loginPage.navigate(); await loginPage.login('admin@test.com', 'WrongPass'); await expect(loginPage.errorAlert).toContainText('Invalid credentials'); }); }); // No new LoginPage() calls in tests // No page.goto('/login') repetition // No locators in the test — all in page objects // Clean, readable test code

Tests should read like a feature specification, not UI automation code. Fixtures + page objects make this achievable.

Authentication State — Login Once for All Tests

// tests/auth.setup.ts — runs once before the test suite import { test as setup, expect } from '@playwright/test'; import path from 'path'; const authFile = path.join(__dirname, '../.auth/user.json'); setup('authenticate', async ({ page }) => { await page.goto('/login'); await page.getByLabel('Email').fill(process.env.TEST_USER!); await page.getByLabel('Password').fill(process.env.TEST_PASS!); await page.getByRole('button', { name: 'Sign in' }).click(); await expect(page).toHaveURL(/dashboard/); // Save session cookies + localStorage to file await page.context().storageState({ path: authFile }); }); // playwright.config.ts — use saved auth projects: [ { name: 'setup', testMatch: /.*\.setup\.ts/ }, { name: 'authenticated tests', use: { storageState: '.auth/user.json' }, dependencies: ['setup'], // setup runs first }, ]

Login once → save cookies → all tests reuse the session. 200 tests don't do 200 login flows. Massive speed improvement.

Multiple Auth Roles

// Multiple setup files for different roles // tests/admin.setup.ts → saves to .auth/admin.json // tests/user.setup.ts → saves to .auth/user.json // playwright.config.ts projects: [ { name: 'setup-admin', testMatch: /admin\.setup\.ts/ }, { name: 'setup-user', testMatch: /user\.setup\.ts/ }, { name: 'admin-tests', use: { storageState: '.auth/admin.json' }, dependencies: ['setup-admin'], testMatch: /admin\/.*.spec.ts/, }, { name: 'user-tests', use: { storageState: '.auth/user.json' }, dependencies: ['setup-user'], testMatch: /user\/.*.spec.ts/, }, ] // Add .auth/ to .gitignore — don't commit credentials! echo ".auth/" >> .gitignore

Session 15 Recap

Fixtures Mastery

  • test.extend() creates custom fixtures
  • Provide + teardown pattern with use()
  • Fixtures inject page objects automatically
  • Import from fixtures file in all tests
  • Composable — fixtures call fixtures

Auth State Strategy

  • auth.setup.ts runs once per project
  • storageState saves cookies + localStorage
  • dependencies: ['setup'] in projects
  • One file per user role
  • Never commit .auth/ to git
