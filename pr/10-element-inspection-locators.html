Playwright Locator Priority Guide

LocatorUsagePriority
getByRole()Button, heading, checkbox, link by ARIA roleUse First
getByLabel()Form inputs associated with a <label>Use First
getByPlaceholder()Input fields with placeholder textUse Often
getByText()Any element containing specific textUse Often
getByAltText()Images with alt attributeUse Often
getByTestId()Elements with data-testid attributeBest Practice
locator('css')CSS selector — when above don't applyFallback
locator('xpath')XPath — last resort onlyAvoid

Rule: Prefer locators that reflect user experience (role, label, text) over technical CSS/XPath selectors.

getByRole — The Most Powerful Locator

// ARIA roles map to semantic HTML elements await page.getByRole('button', { name: 'Submit' }).click(); await page.getByRole('link', { name: 'Sign In' }).click(); await page.getByRole('heading', { name: 'Dashboard', level: 2 }); await page.getByRole('checkbox', { name: 'Remember me' }).check(); await page.getByRole('textbox', { name: 'Email' }).fill('user@test.com'); await page.getByRole('combobox', { name: 'Country' }).selectOption('US'); // Common accessible roles: // button, link, textbox, checkbox, radio, combobox, listbox // heading, img, table, row, cell, dialog, alert, navigation // menuitem, tab, tabpanel, progressbar, slider, spinbutton // exact: false for partial matching await page.getByRole('button', { name: 'Log', exact: false }).click();

If getByRole() doesn't find your element, the first thing to check is: does your HTML have proper ARIA semantics? Fix the app before adding bad locators.

Chaining and Filtering Locators

// Scope locators to a parent element const form = page.getByRole('form', { name: 'Login' }); await form.getByLabel('Username').fill('admin'); await form.getByLabel('Password').fill('secret'); await form.getByRole('button', { name: 'Submit' }).click(); // Filter within a list const listItems = page.getByRole('listitem'); await listItems.filter({ hasText: 'Jane Doe' }).getByRole('button').click(); // nth() — avoid when possible, prefer filter const rows = page.getByRole('row'); await rows.nth(1).getByRole('cell').first().click(); // and() — combine two locators const saveBtn = page.getByRole('button').and(page.getByTestId('save')); // Locator assertions (auto-retry until timeout) await expect(page.getByRole('alert')).toBeVisible(); await expect(page.getByRole('status')).toContainText('Saved');

Chaining locators inside a parent container makes tests more resilient — they only match within that scope.

Inspecting Elements: DevTools + Playwright UI Mode

Browser DevTools

  • F12 → Elements panel
  • Ctrl+Shift+C → click to inspect
  • Right-click element → Copy → XPath/selector
  • Console: $('css') and $x('xpath')
  • Accessibility panel → check ARIA roles

Playwright Codegen

  • npx playwright codegen <url>
  • Click elements — locators auto-generated
  • Shows getByRole/Label/Text preference
  • Generates full test file
  • Use as inspection tool, not final code
// Codegen command npx playwright codegen https://demo.playwright.dev/todomvc // Opens browser + code window — click to generate locator suggestions

data-testid: The Team Approach

Dev adds to HTML

<button class="btn-primary" data-testid="login-submit-btn" > Sign In </button> <input type="email" data-testid="email-input" placeholder="Enter email" />

QE uses in tests

// playwright.config.ts use: { testIdAttribute: 'data-testid' } // In test files: await page .getByTestId('email-input') .fill('user@test.com'); await page .getByTestId('login-submit-btn') .click();

QE should request data-testid attributes from developers. It creates a stable test contract that survives CSS/copy refactors.

Session 10 Recap

Locator Hierarchy

  • getByRole — always try first
  • getByLabel — forms and inputs
  • getByTestId — API contract with dev
  • getByText / getByPlaceholder
  • CSS/XPath — fallback only

Power Techniques

  • Chain/scope locators in parent
  • filter({ hasText }) on lists
  • Codegen for inspection (not final code)
  • DevTools Accessibility panel
  • Configure testIdAttribute once in config
