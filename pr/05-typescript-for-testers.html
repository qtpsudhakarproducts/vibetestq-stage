Type System Interfaces Generics

What is TypeScript?

TypeScript = JavaScript + Types

  • Superset of JavaScript — all valid JS is valid TS
  • Adds static type checking at compile time
  • Compiled to plain JavaScript — browsers never see .ts
  • Maintained by Microsoft, first released 2012

Why Playwright Uses TypeScript

  • IDE autocomplete for the entire Playwright API
  • Catch null reference errors before test runs
  • Self-documenting code — types explain intent
  • Refactoring confidence — rename is safe

You don't need to master TypeScript before starting. Start with JavaScript habits and add types as you go. TypeScript is additive.

Basic Types in TypeScript

// Primitive types const name: string = "Admin"; const age: number = 30; const isAdmin: boolean = true; const nothing: null = null; const unknown: undefined = undefined; // Arrays const tags: string[] = ["smoke", "regression"]; const counts: number[] = [1, 2, 3]; const flags: Array<boolean> = [true, false]; // generic syntax // Tuples — fixed length, fixed types const coordinate: [number, number] = [10, 20]; const userEntry: [string, number] = ["admin", 1]; // Type inference — TypeScript INFERS the type when you assign const baseURL = "https://demo.app"; // inferred as string const timeout = 30000; // inferred as number // TypeScript tracks these — no need to annotate everything // any — escapes type checking (avoid when possible) let anything: any = "could be anything"; anything = 42; // no error anything = true;

TypeScript infers types from assignments. Only annotate when the type isn't obvious or when using function parameters.

Interfaces — Shape Contracts for Test Data

// Define the shape of test data interface UserCredentials { username: string; password: string; role?: string; // ? means optional readonly id: number; // readonly — cannot be changed after creation } // Use the interface const adminUser: UserCredentials = { username: "admin", password: "Admin1234!", id: 1 // role is optional — OK to omit }; // Interfaces for Page Object config interface LoginPageConfig { baseURL: string; timeout?: number; retries?: number; } // Extending interfaces interface AdminUser extends UserCredentials { permissions: string[]; department: string; } const fullAdmin: AdminUser = { username: "admin", password: "Admin1234!", id: 1, permissions: ["read", "write", "delete"], department: "Engineering" };

Use interfaces for all test data objects. You'll get autocomplete, typo detection, and self-documenting code instantly.

Type Aliases & Union Types

// Type alias — give a name to a type type TestStatus = "pass" | "fail" | "skip" | "pending"; type Browser = "chromium" | "firefox" | "webkit"; type Timeout = number | null; // Using union types function setStatus(status: TestStatus): void { console.log(`Status: ${status}`); } setStatus("pass"); // OK setStatus("error"); // TypeScript ERROR — not in union // Type alias vs Interface type Point = { x: number; y: number }; // type alias interface Point2 { x: number; y: number; } // interface // Rule of thumb: // Use interface for object shapes (extensible with extends) // Use type for unions, primitives, and complex types // Intersection types — combine multiple types type AdminConfig = UserCredentials & LoginPageConfig; // Literal types — very specific values type HttpMethod = "GET" | "POST" | "PUT" | "DELETE" | "PATCH"; type StatusCode = 200 | 201 | 400 | 401 | 403 | 404 | 500;

Union types with string literals are perfect for test statuses, environments, and browser names — no more magic strings!

Enums — Named Constants for Tests

// String enum — most useful in test frameworks enum UserRole { Admin = "admin", Manager = "manager", Viewer = "viewer", Guest = "guest" } enum Environment { Development = "http://localhost:3000", Staging = "https://staging.app.com", Production = "https://app.com" } // Usage function loginAs(role: UserRole): void { // TypeScript knows role can only be UserRole values console.log(`Logging in as ${role}`); } loginAs(UserRole.Admin); // Correct // loginAs("admin"); // TypeScript ERROR — use the enum // In playwright.config.ts const BASE_URL = Environment[process.env.ENV as keyof typeof Environment] ?? Environment.Development; // Numeric enum (less common in tests) enum Priority { Low = 1, Medium = 2, High = 3, Critical = 4 }

Enums prevent typos in environment names, user roles, and test categories. Much safer than raw strings.

Typed Functions — The Right Pattern

import { Page } from '@playwright/test'; // Function with typed parameters AND return type async function fillLoginForm( page: Page, username: string, password: string ): Promise<void> { await page.getByLabel('Username').fill(username); await page.getByLabel('Password').fill(password); } // Optional parameters + default values async function navigate( page: Page, path: string, options?: { waitUntil?: 'load' | 'networkidle'; timeout?: number } ): Promise<void> { await page.goto(path, options); } // Function type alias type LoginFunction = (page: Page, creds: UserCredentials) => Promise<boolean>; // Overloads — same name, different signatures function formatInput(value: string): string; function formatInput(value: number): string; function formatInput(value: string | number): string { return String(value).trim(); }

Generics — Reusable Typed Code

// Without generics — loses type information function getFirst(array: any[]): any { return array[0]; } const first = getFirst(["admin", "viewer"]); // first is 'any' — lost type! // With generics — preserves types function getFirst<T>(array: T[]): T { return array[0]; } const firstUser = getFirst(["admin", "viewer"]); // string const firstNum = getFirst([1, 2, 3]); // number // Generic interfaces interface ApiResponse<T> { data: T; status: number; message: string; } interface User { id: number; name: string; } const response: ApiResponse<User> = { data: { id: 1, name: "Admin" }, status: 200, message: "Success" }; response.data.name; // fully typed — knows it's User!

Generics are how Playwright types fixtures. test.extend<MyFixtures>() — you pass your fixture shape as a generic type parameter.

Utility Types — TypeScript's Power Tools

interface UserCredentials { username: string; password: string; role: string; id: number; } // Partial — makes all properties optional type OptionalCredentials = Partial<UserCredentials>; // Can now do: { username: "admin" } — no need for all fields // Required — makes all properties required (reverses Partial) type RequiredCreds = Required<OptionalCredentials>; // Readonly — prevents mutation type ImmutableUser = Readonly<UserCredentials>; const user: ImmutableUser = { username: "a", password: "b", role: "admin", id: 1 }; // user.username = "changed"; // TypeScript ERROR // Pick — extract subset of properties type LoginForm = Pick<UserCredentials, 'username' | 'password'>; // { username: string; password: string } // Omit — exclude properties type PublicUser = Omit<UserCredentials, 'password'>; // { username: string; role: string; id: number } // Record — dictionary type type UserMap = Record<string, UserCredentials>; const users: UserMap = { admin: { username: "admin", password: "...", role: "admin", id: 1 } };

Partial, Pick, and Omit are used constantly in Playwright fixture and config types.

tsconfig.json for Playwright Projects

{ "compilerOptions": { "target": "ES2022", // Compile to modern JavaScript "module": "commonjs", // Node.js module format "lib": ["ES2022", "DOM"], // Available APIs "strict": true, // Enable ALL strict checks (IMPORTANT) "esModuleInterop": true, // Better import compatibility "resolveJsonModule": true, // Allow importing .json files "outDir": "./dist", // Compiled output folder "rootDir": "./", // Source root "baseUrl": ".", // For path aliases "paths": { "@/pages/*": ["./pages/*"], // Path alias "@/helpers/*": ["./helpers/*"] } }, "include": ["**/*.ts"], // Compile all .ts files "exclude": ["node_modules", "dist"] }

Key strict Checks Enabled

  • strictNullChecks — null/undefined must be handled
  • noImplicitAny — no accidental any types
  • strictFunctionTypes — safe callback types

Always Enable "strict": true

This single flag enables all strict type checks. Playwright's official examples use strict mode. Start strict — never regret it later.

TypeScript in Playwright Page Objects

import { Page, Locator } from '@playwright/test'; // Define types at the top of the file interface LoginCredentials { username: string; password: string; } export class LoginPage { // Type the page reference and locators private readonly page: Page; private readonly usernameInput: Locator; private readonly passwordInput: Locator; private readonly loginButton: Locator; private readonly errorMessage: Locator; constructor(page: Page) { this.page = page; this.usernameInput = page.getByLabel('Username'); this.passwordInput = page.getByLabel('Password'); this.loginButton = page.getByRole('button', { name: 'Login' }); this.errorMessage = page.getByRole('alert'); } async login(credentials: LoginCredentials): Promise<void> { await this.usernameInput.fill(credentials.username); await this.passwordInput.fill(credentials.password); await this.loginButton.click(); } async getErrorText(): Promise<string | null> { return await this.errorMessage.textContent(); } }

TypeScript + Page Objects: The combination gives you IDE autocomplete on every page method, preventing typos and wrong parameter types.

TypeScript vs JavaScript: When to Use What

JavaScript — Use When

  • Quick scripts or one-off utilities
  • Prototyping without compilation overhead
  • Team unfamiliar with types at start

TypeScript — Use When (Recommended)

  • Framework projects with multiple contributors
  • Long-lived test suites that need refactoring
  • Working with Playwright (official TS support)
  • You want IDE-powered autocomplete

Playwright officially recommends TypeScript. All examples in this course are TypeScript. Industry standard in 2026 for SDET roles.
