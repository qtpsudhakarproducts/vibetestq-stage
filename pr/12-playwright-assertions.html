Web-First Assertions: Why They're Different

Classic (Bad) Approach

// Check snapshot immediately — FLAKY! const text = await page .getByTestId('status') .textContent(); expect(text).toBe('Saved'); // fails if slow
  • Reads DOM at one instant in time
  • Fails if app not yet updated
  • Forces manual waits before

Web-First (Right) Approach

// Retries until it passes or timeout await expect( page.getByTestId('status') ).toContainText('Saved'); // auto-polls!
  • Automatically retries up to timeout
  • Waits for DOM to settle
  • No manual waits needed

ALWAYS use await expect(locator).* for UI assertions — never read a value and assert separately.

Locator Assertions: The Essential Set

// Visibility await expect(element).toBeVisible(); await expect(element).toBeHidden(); await expect(element).toBeAttached(); // exists in DOM (even if hidden) // Text content await expect(element).toHaveText('Exact match'); await expect(element).toHaveText(/partial match/); // regex await expect(element).toContainText('part of text'); // substring // Form state await expect(input).toHaveValue('expected value'); await expect(checkbox).toBeChecked(); await expect(button).toBeEnabled(); await expect(button).toBeDisabled(); await expect(input).toBeFocused(); // Attributes and CSS await expect(element).toHaveAttribute('href', '/home'); await expect(element).toHaveAttribute('aria-expanded', 'true'); await expect(element).toHaveClass('active'); await expect(element).toHaveCSS('color', 'rgb(255, 0, 0)'); // Count await expect(page.getByRole('listitem')).toHaveCount(5); // Screenshot await expect(element).toHaveScreenshot('component.png');

Page-Level Assertions

// Page URL await expect(page).toHaveURL('https://example.com/dashboard'); await expect(page).toHaveURL(/dashboard/); await expect(page).toHaveURL(url => url.searchParams.has('token')); // Page title await expect(page).toHaveTitle('My App - Dashboard'); await expect(page).toHaveTitle(/Dashboard/); // Full page screenshot await expect(page).toHaveScreenshot('full-page.png'); await expect(page).toHaveScreenshot({ maxDiffPixels: 100 }); // Not assertions — negate with .not await expect(element).not.toBeVisible(); await expect(element).not.toHaveText('Error'); await expect(page).not.toHaveURL(/login/); // Custom timeout override await expect(element).toBeVisible({ timeout: 10000 }); await expect(element).toHaveText('Processing...', { timeout: 30000 });

Use .not to invert any assertion. The retry still applies — it waits for the condition to become NOT true.

Soft Assertions: Collect All Failures

import { test, expect } from '@playwright/test'; test('profile page validation', async ({ page }) => { await page.goto('/profile'); // Soft assertions — test continues even if one fails await expect.soft(page.getByTestId('name')).toHaveText('Jane Doe'); await expect.soft(page.getByTestId('email')).toHaveText('jane@example.com'); await expect.soft(page.getByTestId('role')).toHaveText('Admin'); await expect.soft(page.getByTestId('avatar')).toBeVisible(); // This hard assertion still works after soft failures await page.getByRole('button', { name: 'Edit' }).click(); // Check all soft failures at end expect(test.info().errors).toHaveLength(0); });

Use Soft Assertions When:

  • Validating multiple fields on a form/page
  • Checking a list of items
  • Running bulk data verifications

Use Hard Assertions When:

  • A failure should stop the test
  • Subsequent steps depend on this passing
  • Login / navigation prerequisite checks

expect() for Non-UI Values

// Standard Jest-compatible assertions (no auto-retry) expect(2 + 2).toBe(4); expect('hello').toContain('hell'); expect([1, 2, 3]).toHaveLength(3); expect({ name: 'Jane' }).toMatchObject({ name: 'Jane' }); expect(null).toBeNull(); expect(undefined).toBeUndefined(); expect(value).toBeTruthy(); expect(value).toBeFalsy(); // Number matchers expect(response.status()).toBe(200); expect(items.length).toBeGreaterThan(0); expect(price).toBeCloseTo(9.99, 2); // Array matchers expect(titles).toEqual(['A', 'B', 'C']); expect(tags).toContain('playwright'); expect(tags).toEqual(expect.arrayContaining(['qa', 'test'])); // Object matchers const data = await response.json(); expect(data).toMatchObject({ success: true }); expect(data.user).toHaveProperty('email');

Session 12 Recap

Web-First Assertions

  • Always use await expect(locator).*
  • Auto-retries until condition is true
  • toBeVisible, toHaveText, toHaveValue
  • toBeChecked, toBeEnabled, toBeDisabled
  • .not inverts any assertion

Advanced Patterns

  • Soft assertions — collect multiple failures
  • Page URL and title assertions
  • Screenshot diff comparisons
  • Custom timeout per assertion
  • Standard expect() for non-UI values
