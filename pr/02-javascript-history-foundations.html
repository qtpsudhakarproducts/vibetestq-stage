Why Does History Matter to a Tester?

The Confusion Points

  • Why does var behave so weirdly?
  • Why are there 3 ways to write functions?

The Answer

Every "weird" behaviour in JavaScript has a historical reason. Once you understand why, the how becomes obvious.

Playwright is modern JS. To debug it, you need to know the old JS it was designed to replace.

JavaScript is 29 years old. Playwright is 5. The past explains the present.

Browser Wars: The Dark Ages (1996â€“2004)

Netscape vs Internet Explorer

  • Microsoft cloned JS as JScript
  • Each browser added proprietary APIs
  • Code: if (netscape) else if (IE)
  • Cross-browser testing was a nightmare

ECMAScript to the Rescue

  • 1997: ECMA standardises JS
  • Official name: ECMAScript
  • "JavaScript" is just a brand name
  • ES = the standard; JS = the implementation

This is why testers existed! Cross-browser bugs were so bad that manual testing became a profession. Playwright was built to end this era.

The var vs let vs const Problem

// VAR â€” function scoped, hoisted, re-declarable (the wild west) var count = 1; var count = 2; // No error! Dangerous. if (true) { var x = 10; } console.log(x); // 10 â€” leaks out of if block! // LET â€” block scoped, no hoisting chaos let score = 1; if (true) { let score = 99; } console.log(score); // Still 1 â€” stays in block // CONST â€” block scoped, must assign immediately, cannot reassign const BASE_URL = "https://demo.app"; // BASE_URL = "other"; // TypeError - cannot reassign!

Rule: Use const by default. Use let only when you need to reassign. Never use var.

Arrow Functions â€” Why Playwright Uses Them

// Traditional function â€” has its own 'this' function double(x) { return x * 2; } // Arrow function â€” shorter, captures outer 'this' const double2 = (x) => x * 2; const add = (a, b) => a + b; // Multiline arrow functions need braces + return const processUser = (user) => { const name = user.name.toUpperCase(); return `Hello, ${name}!`; }; // Real Playwright usage â€” every test uses an arrow function callback test('login works', async ({ page }) => { await page.goto('https://demo.app'); const title = await page.title(); expect(title).toBe('Welcome'); });

Arrow functions are the dominant pattern in Playwright. They are not the same as regular functions â€” key difference is lexical this binding.

Spread, Rest & Default Parameters

// Default parameters function navigate(url, timeout = 30000) { console.log(`Going to ${url} with timeout ${timeout}`); } navigate("https://app.com"); // uses default 30000 navigate("https://app.com", 5000); // overrides to 5000 // Spread â€” expand an array/object into individual items const browsers = ["chromium", "firefox"]; const allBrowsers = [...browsers, "webkit"]; // ["chromium", "firefox", "webkit"] // Spread to merge objects const base = { timeout: 30000 }; const overrides = { timeout: 5000, retries: 2 }; const merged = { ...base, ...overrides }; // { timeout: 5000, retries: 2 } // Rest â€” collect remaining arguments function log(level, ...messages) { messages.forEach(msg => console.log(`[${level}] ${msg}`)); } log("INFO", "Test started", "Navigating", "Asserting");

ES Modules: import / export

Exporting

Importing

Every Playwright test file starts with import { test, expect } from '@playwright/test'. Now you know exactly what that means.

Modern Operators: ?. and ??

// Optional chaining â€” safe property access const user = null; // Without optional chaining â€” CRASHES // const name = user.profile.name; // TypeError: Cannot read property of null // With optional chaining â€” returns undefined safely const name = user?.profile?.name; // undefined â€” no crash // Useful in test helpers const errorMsg = await page.locator('.error')?.textContent?.(); // Nullish Coalescing â€” use default when null or undefined const timeout = config.timeout ?? 30000; // If config.timeout is null OR undefined, use 30000 // If config.timeout is 0 or "", KEEPS the value (unlike || which replaces 0 and "") // Combined â€” very common pattern in Playwright config const retries = options?.retries ?? 2; const baseURL = options?.baseURL ?? "https://default.app";

?? vs ||: Use ?? when 0 and empty string are valid values. Use || only for falsy-based defaults.
