test.for() — Data-Driven Tests

import { test, expect } from '@playwright/test'; // test.for() creates one test per data row const loginScenarios = [ { email: 'admin@test.com', password: 'Admin123!', expectedURL: '/dashboard', role: 'admin' }, { email: 'user@test.com', password: 'User1234!', expectedURL: '/home', role: 'user' }, { email: 'qa@test.com', password: 'QA!1234', expectedURL: '/reports', role: 'qa' }, ]; test.for(loginScenarios)( 'login as $role navigates to correct page', async ({ page }, { email, password, expectedURL }) => { await page.goto('/login'); await page.getByLabel('Email').fill(email); await page.getByLabel('Password').fill(password); await page.getByRole('button', { name: 'Sign in' }).click(); await expect(page).toHaveURL(expectedURL); } ); // Generates 3 separate tests in the HTML report: // ✓ login as admin navigates to correct page // ✓ login as user navigates to correct page // ✓ login as qa navigates to correct page

Boundary Value and Validation Testing

// Validation error scenarios const invalidLogins = [ { email: '', password: 'Valid1!', error: 'Email is required' }, { email: 'notanemail', password: 'Valid1!', error: 'Invalid email format' }, { email: 'a@b.com', password: '', error: 'Password is required' }, { email: 'a@b.com', password: '123', error: 'Password too short' }, { email: 'wrong@b.com', password: 'Valid1!', error: 'Invalid credentials' }, ]; test.for(invalidLogins)( 'login shows "$error" for invalid input', async ({ page }, testData) => { await page.goto('/login'); await page.getByLabel('Email').fill(testData.email); await page.getByLabel('Password').fill(testData.password); await page.getByRole('button', { name: 'Sign in' }).click(); await expect(page.getByRole('alert')).toContainText(testData.error); } );

Data-driven validation testing is ideal for form testing — cover all edge cases without duplicating test logic.

Session 17 Recap

Parameterization Tools

  • test.for(array) — one test per data row
  • Dynamic test names with $variable syntax
  • Inline data arrays in spec files
  • External JSON for shared test data
  • Factory functions for generated data

Best Practices

  • Keep test data in fixtures/ folder
  • Never hardcode credentials — use JSON/env
  • Factory functions add timestamp for uniqueness
  • Use TypeScript interfaces for test data types
  • Parameterize fixtures for multi-role testing
