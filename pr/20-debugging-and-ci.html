Debugging Toolkit Overview

UI Mode — Best for Dev

  • npx playwright test --ui
  • Visual test picker with watch mode
  • Click an element to generate locator
  • Time-travel through each test step
  • Network and console tabs per step

Debug Mode

  • npx playwright test --debug
  • Opens Playwright Inspector
  • page.pause() → pause mid-test
  • Step through actions one by one
  • VS Code Playwright extension
npx playwright test --ui # visual runner npx playwright test --debug login.spec.ts # step through npx playwright test --headed --slow-mo=500 # slow motion npx playwright codegen https://myapp.com # record actions

Trace Viewer: Replay Any Test Failure

Enable in Config

// playwright.config.ts use: { trace: 'on-first-retry', // Options: // 'off' - no traces // 'on' - always (slow) // 'on-first-retry'- only when retrying // 'retain-on-failure' } // View a trace file npx playwright show-trace \\ playwright-report/trace.zip

What You See

  • Timeline of every action taken
  • DOM snapshot before and after each step
  • Source code line that triggered action
  • Network requests with full headers
  • Console logs and errors
  • Screenshots at each step

Trace Viewer lets you replay exactly what happened in a failing CI test without having to re-run it. It is your most powerful debugging tool.

GitHub Actions CI Pipeline

name: Playwright Tests on: push: branches: [main, develop] pull_request: branches: [main] jobs: test: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-node@v4 with: node-version: 20 - name: Install dependencies run: npm ci - name: Install Playwright browsers run: npx playwright install --with-deps - name: Run Playwright tests run: npx playwright test env: BASE_URL: ${{ secrets.STAGING_URL }} TEST_USER: ${{ secrets.TEST_USER }} TEST_PASS: ${{ secrets.TEST_PASS }} - name: Upload report uses: actions/upload-artifact@v4 if: always() with: name: playwright-report path: playwright-report/ retention-days: 30

Parallel Sharding Across CI Machines

name: Playwright Sharded Tests jobs: test: runs-on: ubuntu-latest strategy: fail-fast: false matrix: shardIndex: [1, 2, 3, 4] shardTotal: [4] steps: - uses: actions/checkout@v4 - uses: actions/setup-node@v4 with: { node-version: 20 } - run: npm ci - run: npx playwright install --with-deps - run: npx playwright test --shard=${{ matrix.shardIndex }}/${{ matrix.shardTotal }} - uses: actions/upload-artifact@v4 if: always() with: name: blob-report-${{ matrix.shardIndex }} path: blob-report/ merge-reports: needs: test runs-on: ubuntu-latest steps: - uses: actions/download-artifact@v4 with: { path: all-blob-reports, pattern: blob-report-* } - run: npx playwright merge-reports ./all-blob-reports --reporter html - uses: actions/upload-artifact@v4 with: { name: playwright-report, path: playwright-report/ }

Common Failure Patterns and Fixes

Flaky Test Causes

  • Hard-coded waits (waitForTimeout)
  • Race conditions in animations
  • Order-dependent test data
  • Shared state between tests
  • Network timing assumptions

Proven Fixes

  • Use web-first assertions instead of waits
  • Set retries: 2 in CI config
  • Each test creates its own data via API
  • Use fresh BrowserContext per test
  • waitForResponse() instead of timeouts

A flaky test is worse than no test — it erodes trust. Investigate with Trace Viewer, fix root cause, never just add a sleep.
