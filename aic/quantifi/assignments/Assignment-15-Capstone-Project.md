## Part A: UI Tests with POM

### Task 1: Login Tests

In `tests/login.spec.ts`, write tests for:

1. Successful login with valid Admin credentials
2. Login failure with invalid password — assert error message
3. Login with empty fields — assert validation

All tests must use `LoginPage` methods. Zero locators in the test file.

---

### Task 2: Employee Management Tests

In `tests/employee.spec.ts`, write tests for:

1. Add a new employee and verify they appear in the Employee List
2. Search for an employee by name and verify the result
3. Navigate to an employee profile and verify their details are shown

Use `PIMPage`, `AddEmployeePage`, and the login helper. No locators in test files.

---

## Part B: API Tests

### Task 3: API Test Suite

In `tests/api-tests.spec.ts`, write tests for:

1. `GET /pim/employees` — assert status 200 and at least 1 employee exists
2. `POST /pim/employees` — create a test employee and assert the response
3. `DELETE` the test employee created in step 2 and confirm deletion with `GET`

Use the session from UI login for API authentication.

---

## Part C: BDD Scenarios

### Task 4: Cucumber Feature Files

In `features/login.feature`:
- At least 3 scenarios: successful login, failed login, empty form

In `features/employee.feature`:
- At least 2 scenarios: add employee, search employee
- Include a **Scenario Outline** with an Examples table

---

### Task 5: Step Definitions

Implement all step definitions in `step-definitions/`.

All steps must use POM page classes — no inline locators in step definitions.

---

## Part D: Framework Configuration

### Task 6: playwright.config.ts

Configure:
- `baseURL` from `env.config.ts`
- `reporter`: html and json
- `workers`: 2
- `retries`: 1
- `screenshot`: only-on-failure
- `storageState` pointing to the file generated by `global-setup.ts`
- One project: `chromium`

---

### Task 7: buildspec.yml

Create a `buildspec.yml` that:
- Installs Node.js 20 and dependencies
- Installs Playwright browsers
- Runs your full test suite
- Saves the `playwright-report/` as a build artifact
